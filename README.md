# 내시경 리포트 검토 화면 (프로토타입)

AI가 생성한 내시경 리포트 초안을 사람이 확인·수정한 뒤 JSON으로 내보내는
Human-in-the-loop 검토 화면입니다. 의존성 없는 정적 HTML 한 파일입니다.

## 기능

- 좌우 비교: 왼쪽 전사문 / 오른쪽 최종 리포트
- 전사문 **원문 / 의학용어 후보정** 탭 구분, 줄 번호로 위치 지정
- 긴 전사문 검색 + 일치 구간 하이라이트 및 일치한 줄 강조, 일치 건수 표시
- 식도·위·십이지장·주요 소견 직접 편집
- 최초 AI 생성값과 수정값 분리 보관 → 항목 색으로 출처 구분(파랑 = AI 생성 /
  노랑 = 검토자 수정), 수정된 항목은 원본 펼쳐보기
- 필수값(식도·위·십이지장) 비어 있으면 안내 문구 + 내보내기 차단
- 상태 문구: 로딩(스켈레톤) · 빈 전사문 · 생성 실패 항목 · 필수 누락
- 검토 결과를 `original / edited / is_modified` 구조의 JSON 파일로 내보내기

## 화면 설계 기준

- **첫 화면 3초** — 상단에 화면 이름과 "무엇을 하는 화면인지" 한 줄 설명
- **핵심 행동 하나** — 하단 바에 `리포트 내보내기` 버튼 하나만 강조, 나머지는 보조
- **상태를 말하는 화면** — 로딩·빈 데이터·필수 누락마다 전용 문구
- **버튼은 동사** — "확인"이 아니라 "리포트 내보내기"
- **일관성** — 색 2개(AI 파랑 · 수정 노랑) + 중립 회색, 글꼴 1개, 간격 8px 배수

데스크톱 검토 환경 기준으로만 설계했습니다(모바일 대응 없음).

## 실행

```bash
open index.html
```

또는 로컬 서버:

```bash
python3 -m http.server 4173
```

## 배포 (Vercel)

프레임워크 없는 정적 사이트입니다.

1. Vercel에서 이 저장소를 Import
2. Framework Preset: **Other**
3. Build Command / Output Directory: 비워 둠 (루트의 `index.html`을 그대로 서빙)

## 데이터

`index.html` 안의 `CASES` 배열이 샘플 3건(정상 / 필수 항목 누락 / 전사문 없음)을
담고 있습니다. **모두 가공된 예시 문장이며 실제 환자 기록이 아닙니다.**
기업 제공 샘플을 받으면 이 배열과 필드 규격을 교체합니다.

내보내기 JSON 형태:

```json
{
  "case_id": "EGD-2026-0001",
  "meta": { "model_version": "...", "prompt_version": "...", "exported_at": "..." },
  "transcript": { "raw_text": "...", "corrected_text": "..." },
  "report": {
    "esophagus": { "original": "...", "edited": "...", "is_modified": false }
  },
  "review_status": "completed"
}
```

## 아직 구현하지 않은 것

과제의 도전 과제 영역: 이탈 경고, 임시 저장, 근거 문장 하이라이트 연결,
오디오 재생, 수정 이력/되돌리기, 단축키, Diff 화면, 진행 현황 표시.
